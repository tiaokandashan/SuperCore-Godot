# 文档维护规范

状态：当前有效  
适用范围：`Docs` 当前文档、方案、日志和归档  
最后更新：2026-08-06  
AI阅读优先级：高

## 一、事实优先级

1. 当前源码、资源、配置和工作区。
2. 标记为当前有效的 `Docs/01-04` 文档。
3. 进行中任务方案和结构化日志。
4. 已完成方案与历史归档。
5. Unity 迁移源与已删除旧 Godot 资料。

低优先级资料不能覆盖高优先级事实。

## 二、状态

- `当前有效`：描述当前实现，可以作为修改依据。
- `待补充`：仅保留路由，不表示能力存在。
- `待确认`：方案尚未获得实施授权。
- `进行中`：方案已确认，任务未完成。
- `已完成`：方案已落地，只用于过程追溯。
- `已过期`：已知不符合当前实现。
- `历史归档`：只用于追溯。

## 三、目录职责

- 项目级规范和总索引放在 `01_项目总览`。
- Module、Editor 工具和业务当前事实分别放在 `02_模块手册`、`03_编辑器工具`、`04_业务`。
- 方案放在 `05_任务` 对应状态目录，正式任务详情放在 `06_日志`。
- 失效长文档放在 `90_历史归档`。

## 四、维护规则

- 修改功能前读取相关当前文档，修改后复核文档是否仍准确。
- 尚未迁移的功能只保留待补充文件，不复制 Unity 内容冒充 Godot 事实。
- 当前文档过期时先核对实际文件，再修正、归档或标记状态。
- 总览和索引只保留路由与硬结论，详细事实写入对应领域目录。
- 文档不复制大段源码、历史方案或对话内容。

## 五、文件处理

- 文本统一使用 UTF-8 无 BOM。
- 读取文本显式使用 UTF-8；定向修改优先使用 `apply_patch`。
- 修改前读取当前内容并保留用户已有的无关差异。
- 移动、重命名和删除前确认精确源与目标；有追溯价值的内容优先归档。
- 不在文档操作中修改 `Project/.godot` 生成缓存。

## 六、日志要求

每次修改日志都必须说明文档处理、自审和验证结果。无法执行的验证写明原因，不省略也不伪造成功。
