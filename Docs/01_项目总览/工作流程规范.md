# 工作流程规范

状态：当前有效  
适用范围：查询、实现、修复、重构、迁移、资源配置和文档修改  
最后更新：2026-08-06  
AI阅读优先级：高

## 一、核心原则

- 先理解当前实现和 Unity 迁移源，再讨论修改。
- 先模拟方案与风险，再修改文件。
- 最终方案形成后，必须等待用户独立消息精确回复 `确认实现`。
- 有效确认只授权其前一版最终方案，不授权范围外修改、删除、发布或远端操作。
- 一次只完成一个可独立验证的迁移阶段，不用后续阶段掩盖当前失败。

## 二、查询流程

查询只读取入口、相关当前文档、实际代码、资源和配置，直接报告证据、风险与未验证边界，不创建任务、索引或日志。

查询中发现问题只报告；用户要求修复、保存报告或更新文档时，重新归类为修改并等待确认。

## 三、简单修改

1. 读取入口、工作流程、任务索引、相关文档和实际目标。
2. 搜索源实现、目标调用点和未提交差异。
3. 给出修改文件、行为、风险、不做事项和验证方法。
4. 自审方案没有越过当前迁移阶段。
5. 给出最终方案并等待 `确认实现`。
6. 确认后创建任务，填写根任务和直接依赖，再实施。
7. 完成自审、验证、当前文档、索引和日志。

## 四、复杂修改

复杂任务涉及公共 API、多个模块、资源格式、Editor、构建链路或阶段架构：

1. 重新读取入口、相关规范、根任务和实际源代码。
2. 在 `Docs/05_任务/待确认` 编写具体方案。
3. 方案必须写目标、现状、源与目标、职责、范围、不做事项、步骤、依赖、风险和验证。
4. 用户有效确认后创建任务，把方案移入 `进行中` 并填写 `root_task`。
5. 实施中发现必须扩大范围时停止，更新方案并重新确认。
6. 完成后将方案移入 `已完成`；暂停时移入 `搁置`。

## 五、唯一有效确认

只有去除首尾空白后整条消息完全等于以下内容才有效：

```text
确认实现
```

带标点、说明、引用或其他前后缀均不算确认。方案形成前的预先授权不能跨任务复用。

## 六、迁移边界

- Unity 源工程只读；未经单独方案与确认不得修改。
- 不恢复已删除的旧 Godot 迁移，不保留旧路径、类型或配置兼容。
- 尚未审计的 Unity 能力不预先宣称保留、删除或映射。
- 尚无真实消费者时不创建空 Module、配置或编辑器页面。唯一当前例外是用户在 `SCG-20260810-003` 中明确授权的 12 个 Module 与模块自有配置启动骨架；它们不得被视为功能迁移完成，也不能扩展出未确认 API。
- 代码、资源、生成、构建和发布分别按实际任务授权，不由根任务自动扩大权限。

## 七、实现后审查

- 是否只修改任务目标文件。
- 是否符合 SuperCore、Module、Procedure、GameSystem 和 Editor 职责。
- 是否同步全部公共 API 调用点。
- 是否存在 Node、Resource、信号、事件、计时、异步或资源句柄泄漏。
- 是否产生无关兼容层、自动写回或构建产物。
- 验证是否足以证明当前阶段，不把未验证内容写成通过。
